Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talking to a FastAPI service that serves filtered, in-memory mock data. There is no database.

System architecture

Three tiers, all running locally. The browser calls the API directly over HTTP; CORS is open.

Tech stack

Versions come from client/package.json and server/pyproject.toml.

Frontend

  • Vue 3 (^3.4), setup() with ref / computed
  • vue-router 4, history mode
  • axios for HTTP
  • Vite 8 dev server and bundler, port 3000
  • Custom SVG charts and CSS Grid, no chart library
  • English and Japanese locales

Backend

  • Python 3.11+, FastAPI
  • Uvicorn ASGI server, port 8001
  • Pydantic v2 response models
  • Managed with uv
  • CORS enabled for all origins

Data flow

How a filter change on screen becomes a filtered response.

Request path

  1. The user changes a filter in FilterBar. State lives in useFilters, a module-level singleton shared by every view.
  2. The view calls getCurrentFilters() and passes the result to a method in api.js. Values equal to all are dropped.
  3. api.js sends GET /api/...?warehouse=&category=&status=&month= with axios.
  4. FastAPI runs apply_filters and filter_by_month over the in-memory lists. Quarters such as Q3-2025 expand to three months.
  5. The result is validated against the Pydantic response_model and returned as JSON.
  6. The view stores raw data in refs and derives totals and chart series in computed properties.

GET /api/backlognone; adds has_purchase_order
GET /api/spending/*none (summary, monthly, categories, transactions)

Inventory has no month filter because inventory records carry no order date.

Observations

Things worth knowing, found while reading the code.

StatusFinding
Gap api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get by backlog item). main.py defines purchase-order Pydantic models but no routes for either, so those calls would return 404.
Note Data is loaded once at import and lives in module-level lists. Edits to the JSON files need a server restart, and any in-memory writes would be lost on restart.
Note The API base URL is hard-coded to http://localhost:8001/api in api.js, and CORS allows all origins. Fine for a local demo, not for deployment.
Info useFilters keeps filter state at module scope, so every view shares one set of filters and they persist across route changes.
Good Backend tests cover dashboard, inventory, and the remaining endpoints, using FastAPI's TestClient.
